# Decisions

Each significant choice, why it was made, and what would change it. Newest last.

| # | Date | Decision | Why | Revisit if |
|---|------|----------|-----|-----------|
| D1 | 2026-11-09 | Working name **Faultline**. Do not use Netflix's names, logos or "Chaos Monkey" in the product. | Original product inspired by Netflix's published design; avoids trademark and impersonation issues. | Superseded by D19 on 2026-11-10. |
| D2 | 2026-11-09 | **Python 3.14 with uv**, FastAPI, pydantic, SQLAlchemy, Typer. | Your choice: readable, matches your other projects, mature Kubernetes and AWS libraries. Go (Netflix's choice) was the alternative. | Performance or single-binary distribution becomes a requirement. |
| D3 | 2026-11-09 | Real targets in M3 will be **Kubernetes pods and AWS EC2 / auto-scaling groups**, behind one small driver interface (list targets, terminate one). | Your choice: covers container and VM estates; more clouds can be added later. | A customer needs Azure or GCP first. |
| D4 | 2026-11-09 | **Termination only.** No shell, SSH or arbitrary commands, ever, in this product line. | Netflix dropped SSH-based actions in Chaos Monkey 2.0; for a fintech it also removes the most dangerous permission a chaos tool could hold. | Latency and failure injection (the "Later" milestone) will be designed separately, ChAP-style, not via shell access. |
| D5 | 2026-11-09 | Keep Netflix's **scheduling algorithm** (daily weighted coin, p = 1 / mean working days; random time in working hours; target chosen at kill time), its defaults (off, leashed, not scheduling; mean 2 days, minimum 1 day; grouping by cluster) and its vocabulary (app, stack, cluster, exceptions, leashed). | Proven in production at Netflix and easy for owners to reason about. Familiar to anyone who knows Chaos Monkey. | Customers ask for experiment types beyond termination. |
| D6 | 2026-11-09 | **12 safety guards**, all of which must agree, checked at kill time (not at planning time). The kill switch is read again immediately before the platform call, and an intent entry is audited first. | A guard checked only when planning can be hours stale. The second kill-switch read closes the gap between deciding and acting. | — |
| D7 | 2026-11-09 | **Fail closed** on doubt: an incident source that errors counts as an open incident; a group that does not recover by its deadline switches the kill switch on for everyone. | In a bank, a missed test costs little; an unwanted outage costs a lot. | — |
| D8 | 2026-11-09 | **Maker-checker approvals bound to a configuration version.** Any change to an app voids its approval. Approvers can never approve their own request or a configuration they last changed. Admins cannot approve. Approvals expire (default 90 days). | Change management expectations in SOX, PCI DSS, SOC 2 and DORA; separation of duties between configuring the platform and accepting risk. | A customer's change process is integrated directly (for example ServiceNow), in which case the change ticket can replace the in-app approval. |
| D9 | 2026-11-09 | Daily and concurrency caps apply to **live kills only**; the minimum gap applies to dry runs too. | Dry runs must not use up the live budget, but should still show a realistic schedule. | — |
| D10 | 2026-11-09 | **Hash-chained audit log**, HMAC-signed with a key held outside the database (required in production). Truncation of the newest entries is caught by checking a head recorded elsewhere (`audit verify --expect-head`). | Detects edits and deletions even by someone with database write access. We say plainly what it cannot detect on its own. | M4 adds shipping to write-once storage (for example S3 Object Lock) and database grants that forbid UPDATE and DELETE on the table. |
| D11 | 2026-11-09 | **Secrets only from environment variables.** The loader refuses a config file containing `audit_key`, `dev_signing_key` or a database password. | Netflix's Chaos Monkey keeps passwords in plaintext config; that fails any security review. | A secrets manager integration is added (M4). |
| D12 | 2026-11-09 | **Production refuses to start** until every readiness check passes (PostgreSQL, audit key, single sign-on, no dev tokens, TLS, exact host names, a real driver). | Misconfiguration is the most common way secure software ends up insecure. | — |
| D13 | 2026-11-09 | Sign-in is **OpenID Connect bearer tokens** verified against the provider's published keys, asymmetric algorithms only; roles come from identity-provider groups. Local development tokens exist only in development mode. | Works with Okta, Entra ID and Google without storing passwords. Asymmetric-only removes the algorithm-confusion class of attacks. | — |
| D14 | 2026-11-09 | In production the **CLI only reads and breaks glass** (kill switch on, declare an incident). All other changes go through the API. | Every change must be tied to a signed-in person; CLI identity is only the operating-system user name. | — |
| D15 | 2026-11-09 | One process runs the **API and the executor**; replicas coordinate with a database **lease**, a unique constraint per group per day, and conditional updates when claiming a kill. | Simple to deploy now, safe to scale to two or more replicas. | Load or isolation needs justify separate deployments (M4). |
| D16 | 2026-11-09 | Schema created with `create_all` for now. **Alembic migrations before the first production release (M4).** | No deployed version exists yet, so there is nothing to migrate. | Before M4 ships. |
| D17 | 2026-11-09 | Rate limiting is **in memory, per replica**, per client address. | Enough for one replica; a gateway limit is still advised in production. | Running several replicas behind a load balancer (M4). |
| D18 | 2026-11-09 | Test client uses **httpx2**, as Starlette 1.10 now asks. | Removes a deprecation warning; the old httpx path will stop working. | — |
| D19 | 2026-11-10 | Product name is **Chaos Monkey** (your choice; supersedes D1). Package and command `chaosmonkey`, settings file `chaosmonkey.toml`, environment variables `CHAOSMONKEY_*`. The README says it is an independent implementation, not affiliated with or endorsed by Netflix; no Netflix logo, branding or code. | The name says exactly what the product does, and engineers already know it. | **Legal risk to check:** "Chaos Monkey" is the name of Netflix's open-source tool, and its Apache licence gives no right to use its names. Fine for building and internal use; get legal advice before selling or publishing under this name, and rename if Netflix objects. |
